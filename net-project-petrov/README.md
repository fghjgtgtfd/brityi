## Описание
TCP-сервер реализует сетевой менеджер списка задач (To-Do List) на C++. Сервер позволяет добавлять новые задачи (в том числе с высоким приоритетом `HIGH` или обычным `LOW`), просматривать отсортированный по важности список, отмечать задачи выполненными, удалять их, получать статистику и очищать список. Все задачи автоматически сохраняются в файл `todo.txt` и восстанавливаются после перезапуска сервера.

## Как собрать и запустить

### Windows (MinGW / g++)
```bash
g++ server.cpp -o server.exe -lws2_32
g++ client.cpp -o client.exe -lws2_32
```
Запуск в двух отдельных окнах терминала:
```bash
server.exe
client.exe
```

### Linux (g++)
```bash
g++ server.cpp -o server
g++ client.cpp -o client
```
Запуск в двух отдельных терминалах:
```bash
./server
./client
```

## Таблица команд протокола

Команды принимаются в любом регистре (`add`, `ADD`, `Add`). Элементы списка в ответе разделяются символом `;`.

| Команда | Аргументы | Описание | Пример ответа сервера |
| :--- | :--- | :--- | :--- |
| `ADD` | `[HIGH\|LOW] <текст>` | Добавить задачу (с приоритетом или без) | `OK, task 1 [HIGH]` |
| `LIST` | Нет | Вывести все задачи (сначала важные `[HIGH]`) | `1) [HIGH] finish lab; 2) [x] buy milk` или `List is empty` |
| `DONE` | `<номер>` | Отметить задачу выполненной `[x]` | `OK, task 2 marked as done` |
| `DEL` | `<номер>` | Удалить задачу по номеру | `OK, task 1 deleted` |
| `COUNT` | Нет | Показать общее число задач и выполненных | `total 2, done 1` |
| `CLEAR` | Нет | Полностью очистить список задач | `OK, list cleared` |
| `HELP` | Нет | Показать список команд и примеры | `Commands: ADD buy milk \| ADD HIGH finish project ...` |
| `QUIT` | Нет | Завершить сеанс работы с сервером | `BYE` |
| *Ошибка* | *Некорректные данные* | Пустой текст, неверный номер, неизвестная команда | `ERROR invalid task number` |

## Ответы на контрольные вопросы

1. **В каком порядке сервер вызывает `socket`, `bind`, `listen`, `accept` и что делает каждый вызов?**
   * `socket()` — создаёт дескриптор сетевого сокета (указывается семейство адресов IPv4 `AF_INET` и потоковый протокол TCP `SOCK_STREAM`).
   * `bind()` — привязывает созданный сокет к конкретному IP-адресу (`INADDR_ANY`) и номеру порта (`9000`) на локальной машине.
   * `listen()` — переводит сокет в пассивный режим прослушивания входящих запросов на подключение и задаёт размер очереди ожидающих клиентов.
   * `accept()` — извлекает первый запрос из очереди подключений, блокируя выполнение до прихода клиента, и возвращает новый сокет для обмена данными именно с этим клиентом.

2. **Почему клиенту не нужны `bind` и `listen`? Какой порт получает клиент?**
   * Клиент не ожидает входящих подключений извне, а сам инициирует соединение с сервером с помощью вызова `connect()`. При вызове `connect()` операционная система автоматически назначает клиентскому сокету любой свободный временный (эфемерный) порт из динамического диапазона.

3. **Зачем нужен `htons(PORT)`?**
   * Функция `htons` (*Host TO Network Short*) переводит 16-битный номер порта из порядка байтов процессора компьютера (на архитектуре x86 используется *Little-Endian*) в единый сетевой стандарт передачи данных (*Big-Endian*), чтобы все узлы сети одинаково интерпретировали номер порта.

4. **Почему `recvLine` читает до символа `\n`, а не просто вызывает `recv` один раз?**
   * Протокол TCP является потоковым (передаёт непрерывный поток байтов без границ сообщений). За один вызов `recv()` может прийти только часть отправленной строки (из-за фрагментации пакетов) либо сразу несколько команд подряд, поэтому чтение выполняется в цикле до символа конца строки `\n`.

5. **Опишите протокол своего варианта: какие команды, какие ответы, что сервер делает при ошибке.**
   * Протокол текстовый, обмен происходит построчно с разделителем `\n`. При подключении сервер отправляет приветствие со списком команд. Клиент отправляет команды (`ADD`, `ADD HIGH/LOW`, `LIST`, `DONE`, `DEL`, `COUNT`, `CLEAR`, `HELP`, `QUIT`), сервер отвечает ровно одной строкой (`OK...`, перечнем задач через `;`, статистикой `total X, done Y` или `BYE` при выходе). При любой ошибке ввода (неизвестная команда, пустой текст задачи, несуществующий номер) сервер не завершает работу, а возвращает строку, начинающуюся с `ERROR` и описанием причины.
